# Зачем нужен Docker

Представьте, что приложение работает на вашем компьютере, но не запускается у коллеги. У вас установлена Node.js 24, у него Node.js 20. У вас PostgreSQL слушает порт `5432`, у него этот порт занят. Кроме кода приходится отдельно объяснять, какие программы поставить и как их настроить.

Docker позволяет описать окружение рядом с кодом и запускать его предсказуемым способом.

## Без Docker

Обычный запуск требует подготовить компьютер:

```text
компьютер разработчика
├── Node.js нужной версии
├── pnpm нужной версии
├── PostgreSQL
├── системные библиотеки
└── переменные окружения
```

Чем больше системных зависимостей, тем выше вероятность фразы «у меня работает».

## С Docker

Приложение запускается в изолированном окружении:

```text
компьютер разработчика
└── Docker
    ├── container приложения
    │   └── Node.js нужной версии
    └── container базы данных
        └── PostgreSQL нужной версии
```

У каждого контейнера свои процессы, файловая система и сетевое окружение. При этом контейнеры используют ядро хоста, поэтому обычно легче полноценных виртуальных машин.

## Что Docker даёт на практике

- Одинаковую версию runtime у разработчиков и в deployment.
- Быстрый запуск базы данных без ручной установки в систему.
- Изоляцию зависимостей разных проектов.
- Воспроизводимую сборку приложения по `Dockerfile`.
- Описание нескольких сервисов одним `compose.yaml`.

## Чего Docker не делает

Docker не исправляет ошибки приложения, не создаёт резервные копии автоматически и не делает container полностью безопасным. Если удалить container без отдельного хранилища, записанные внутрь данные можно потерять.

## Первая модель в голове

Пока запомните три термина:

1. `Dockerfile` — инструкция, как подготовить приложение.
2. Image — результат подготовки, похожий на шаблон.
3. Container — запущенный экземпляр шаблона.
