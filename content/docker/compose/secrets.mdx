# Secrets

Переменная окружения удобна, но может случайно попасть в лог, диагностический вывод или дамп процесса. Пароли, API-ключи и сертификаты нельзя запекать в Dockerfile, image или публичный `.env`.

Compose secret передаётся только указанному сервису и монтируется read-only файлом `/run/secrets/<name>` в Linux-container. Приложение читает файл во время запуска.

## Сначала создаём локальный файл

```bash
mkdir -p secrets
printf 'development-password' > secrets/postgres_password.txt
```

Добавьте `secrets/` в `.gitignore` и `.dockerignore`. Значение выше подходит только для локального обучения.

## Runtime secret

```yaml
services:
  database:
    image: postgres:17-alpine
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
    secrets:
      - postgres_password

secrets:
  postgres_password:
    file: ./secrets/postgres_password.txt
```

Каталог `secrets/` исключите из Git и build context. Суффикс `_FILE` — соглашение конкретного образа, а не автоматическая возможность любого приложения. Собственное приложение должно само прочитать файл.

```ts
import { readFile } from 'node:fs/promises'

const password = (
  await readFile('/run/secrets/postgres_password', 'utf8')
).trim()
```

## Build secret

Для приватного registry во время сборки используйте BuildKit secret:

```dockerfile
# syntax=docker/dockerfile:1
FROM node:24-alpine AS build
WORKDIR /app

RUN --mount=type=secret,id=npmrc,target=/root/.npmrc \
  npm ci
```

```bash
docker build \
  --secret id=npmrc,src="$HOME/.npmrc" \
  --tag handbook:production \
  .
```

Secret доступен только для выбранной `RUN` и не сохраняется в слое. Не заменяйте его `ARG NPM_TOKEN`: build args не предназначены для секретов.

## Ограничения

Локальный Compose secret из файла защищает от случайного попадания значения в environment и образ, но файл на хосте всё равно требует корректных прав и управления. В production часто нужен внешний secret manager с ротацией и аудитом.
